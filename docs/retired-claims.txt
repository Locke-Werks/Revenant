# Claims this project has retired.
#
# A fact here gets stated in three or four places, because a comment that
# records the measurement beside the code is the habit that makes this tree
# worth reading. The cost is that correcting the fact in one place leaves the
# other copies asserting the old thing, in files a reader trusts and acts on.
# Nine of those were found in a single day and the fix for one of them
# introduced another. Every numeric claim a verifier rebuilt from scratch
# reproduced; the prose about the arithmetic was the part that lied.
#
# So the retraction gets recorded. scripts/check_retired_claims.py walks every
# tracked file looking for each phrase below and fails naming the file and the
# line. The first correction is not what this is for. The fifth copy is, three
# months from now, pasted by somebody who read a file nobody had swept.
#
# WHEN YOU RETRACT SOMETHING, ADD IT HERE IN THE SAME COMMIT. The check then
# finds every other copy for free, which is the whole return on the two minutes
# this file costs.
#
#
# FORMAT
#
# Records are separated by a blank line. Comment lines start with #. Within a
# record, each line is `key: value`, and a line that starts with whitespace
# continues the one above it.
#
#   phrase   The wording to hunt for. Repeat the key for variants of the same
#            retired fact; one record per fact, not per sentence. Pick the most
#            distinctive clause, roughly six to fifteen words. The match is
#            case-insensitive and whitespace-normalised, so the line wrapping,
#            the backticks and the capitals do not matter and a claim split
#            across two comment lines is still found. Under 24 normalised
#            characters is refused: a phrase that short matches half the tree.
#
#            THE PHRASE HAS TO CARRY ITS OWN SUBJECT. Seeding this file turned
#            up "on both devices in the conformance matrix", retired in
#            tests/engine/test_engine_passband.cpp because the spectrum kernel
#            is refereed on one device. The same clause is true, twice, of
#            pfb_fft in core/dsp/spectrum_reference.h and
#            core/shaders/spectrum.comp, which are gated by nothing and do run
#            on both. A clause with the subject left out is a claim about
#            whatever sentence it lands in, so it was not listed. Length is not
#            the test and the 24-character floor would not have caught it.
#
#            IT ALSO HAS TO BE THE WORDING THAT WAS THERE. A retraction that
#            paraphrases what it withdrew, "thirteen, twice" in
#            core/dsp/vrx_reference.h, leaves this check nothing to hunt for.
#            Quote the old sentence.
#   retired  YYYY-MM-DD, the day it stopped being true.
#   commit   The change that made it false, where there is one. Otherwise the
#            change that recorded the retraction.
#   instead  One line on what is true now. This is what the failure prints, so
#            write it for somebody who has just been stopped by it.
#
#
# QUOTING A RETIRED PHRASE ON PURPOSE
#
# The convention here is to leave the old wording visible under WHAT THIS
# PARAGRAPH USED TO SAY, so a retired phrase sits, deliberately, right next to
# its own correction. That keeps working. An occurrence is allowed when a
# retraction marker appears on its line or within the 30 lines above it, and
# the markers are the words this tree already writes:
#
#   used to say     used to mean     used to read     now false
#   said the opposite
#
# Nothing else. In particular the bare words "retracted" and "retraction" are
# not markers, because they turn up in prose about a retraction that lives in
# another file, and one of those sits 25 lines above a claim this check was
# written to catch.
#
# Proximity rather than a list of allowed file-and-line pairs, for two reasons.
# An allowlist records WHERE a phrase may appear, which is a second copy of the
# fact this mechanism exists to stop duplicating, and it rots the first time
# somebody inserts a line above the entry. Proximity records WHY the occurrence
# is legitimate, and that reason travels with the text through every reflow and
# every file move.
#
# It can be abused: paste a marker beside a stale claim and it goes quiet. That
# is a deliberate lie in a diff with the words "used to say" on it, which a
# reviewer can see. An allowlist entry is a line number nobody reads.
#
#
# WHAT THIS CANNOT DO
#
# It catches a false statement coming back. It cannot catch a true statement
# going missing. core/rpc/revenant.capnp described EngineInfo.sourceCenter
# without saying it moves, which was as wrong as the copies that said it does
# not, and there was no phrase to list. That one needs a reader.

phrase: minimum distance 5, so some weight-3 error patterns are a weight-2

phrase: the RDS checkword has minimum distance 5
retired: 2026-09-21
commit: 30b2ded
instead: The code's minimum distance is 3. Enumerated twice independently over
    all 65535 non-zero codewords of g(x) = x^10 + x^8 + x^7 + x^5 + x^4 + x^3
    + 1: seven codewords of weight 3, three of weight 4, forty-five of weight
    5, and the narrowest non-zero codeword spans eleven bits, which is where EN
    50067 clause 2.3's "about 99.8 percent of bursts spanning 11 bits" comes
    from. The 5 was the burst-correcting length l = (n-k)/2 from the Rieger
    bound, read as a Hamming distance; EN 50067 never claims distance 5.
    Rewriting into a different valid block therefore starts at weight TWO, not
    three: 21 of the 325 weight-2 patterns at the shipped correctable span of
    2, and a two-bit error is one the standard undertakes only to detect. The
    undetectable floor starts at weight three, where those seven codewords
    arrive with a zero syndrome and are delivered as clean with the wrong
    contents. core/decode/rds_groups.h has the measured table.
