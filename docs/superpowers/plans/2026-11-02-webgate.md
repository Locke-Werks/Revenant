# Webgate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An installed iPhone web app that controls and listens to Revenant over the LAN, served by a new `revenant-webgate` process beside the engine.

**Architecture:** `revenant-webgate` is an ordinary RPC client of the engine over loopback (`revenant_rpc_client`), and an HTTPS/WebSocket server to phones on the LAN (kj-http + kj-tls). It reshapes engine streams for a phone: max-pooled uint8 spectrum, Opus for live audio, AAC/HLS for background audio. The app in `web/` is framework-free TypeScript bundled by esbuild, installed to the home screen as a PWA.

**Tech Stack:** C++23, Cap'n Proto/kj (kj-http, kj-tls), OpenSSL, libopus, Windows Media Foundation (AAC), Catch2; TypeScript, esbuild, WebGL, AudioWorklet, WASM Opus decoder, Node's built-in test runner (build time only).

**Spec:** `docs/superpowers/specs/2026-11-02-webgate-design.md`

## Global Constraints

- HTTPS and WebSocket on port **17700**; plain HTTP on **17701** serving only `/ca` and a redirect. Both bind `0.0.0.0`.
- Engine reached only on loopback, default `127.0.0.1:17690`, with the engine token from the locations in `docs/rpc.md`. The phone never sees the engine token. No phone-side authentication.
- State directory `%LOCALAPPDATA%\Revenant\webgate\` holding `ca.key`, `ca.crt`, `server.key`, `server.crt`; key files ACL'd like the RPC token (owner and SYSTEM only).
- Server certificate SANs: hostname, `<hostname>.local`, every current LAN IPv4 address. No IPv6 anywhere (owner, 2026-11-02). Reissued from the same CA when that set changes.
- No engine schema changes.
- Spectrum: about 20 fps, max-pool to the phone's pixel width, uint8 dB, at most one frame in flight per socket, skipped frames counted not queued.
- Live audio: Opus, 48 kHz mono, 20 ms frames, about 32 kbit/s; drop oldest when the socket backs up. Client jitter buffer starts near 80 ms.
- Background audio: AAC-LC in fMP4, 1 s segments, via Media Foundation; encoding continues 30 s after switching back to live.
- App installed from `https://<hostname>.local:17700/`; manifest `display: standalone`; service worker caches the shell only, never streams or control.
- Node is a build-time tool only; the payload carries no Node runtime.
- New vcpkg dependencies: `libopus`, `capnproto` feature `openssl`. Nothing else.
- Commit locally only; do not push (CI runs only at release). Commits as `Locke Werks <archon@lockewerks.com>`, no AI attribution trailers.
- No em dashes in code comments, docs or commit messages.

## Review Focus

1. Engine with no source open: `SpectrumGeometry.bins == 0`, no frames. The app must show "no radio open" and the radio panel, not a blank waterfall. Test in Task 10.
2. View narrower than one engine bin (zoomed past resolution): pixels outnumber bins in the span. Each pixel takes the bin under its centre; never a zero or empty value. Test in Task 6.
3. Rotation mid-stream: `setView` with a new `widthPx` while frames are in flight. The next frame sent is cut for the new view and its header says so; no frame of the wrong width reaches the app. Test in Task 10.
4. A second radio opened (`openSource`) at a different sample rate: `everyNth` is recomputed from the new block rate so frame rate stays near 20 fps. Test in Task 10.
5. Two phones connected at once: each owns its own receivers; one closing removes only its own. Test in Task 11.
